# 프로젝트 개요

## 직접 요구

- 기획 문서를 다른 협업자에게 공유할 수 있는 형태로 깔끔하게 관리한다.
- 실행 가능한 게임 코드도 기획 문서와 같은 프로젝트 폴더에서 관리한다.
- 공개하면 안 되는 원본도 같은 프로젝트 폴더에 두되 GitHub에는 올리지 않는다.
- 구조 변경 뒤에도 이전 문서와 작업에서 사용한 경로를 가능한 한 찾아갈 수 있게 한다.
- 현재 실제로 다루는 다섯 게임만 정리하고, 현재 범위 밖의 후보에는 작업 비용을 쓰지 않는다.
- 공개 저장소는 협업과 열람을 위한 것이며 원본 코드와 창작물의 재사용을 허용하지 않는다.
- 원안 검토자에게는 플레이 가능한 링크와 확인용 기획 문서를 함께 전달한다.
- 현재 코드와 공개 문서는 GitHub 공개 저장소에 게시하고, 게임 웹 배포는 별도로 진행한다.

## 사용자 결정

- 저장소 하나에 여러 독립 게임을 두는 모노레포를 사용한다.
- 각 게임의 정식 단위는 `games/<slug>/`이며 실행 코드와 관련 문서를 함께 둔다.
- 공개 코드·문서와 로컬 전용 원본을 분리하고, 로컬 전용 영역은 Git에서 제외한다.
- 공개 기획 문서는 원본 경로나 개인 정보를 쓰지 않고 `SRC-*` 식별자로 근거를 표시한다.
- 이전 코드 경로는 로컬 호환 별칭과 경로 변환표로 보조하며, 새 문서에서는 정식 경로만 쓴다.
- 공개 가능한 이전 레이아웃을 먼저 기준선 커밋으로 남기고, 다음 커밋에서 새 구조로 이동해 Git 이력에서도 변경을 추적할 수 있게 한다.
- 공개 표시명은 `노래에서 태어난 게임들`, GitHub 저장소명은 `born-from-songs`로 한다.
- 공개 크레딧에는 희진의 원안·크리에이티브 디렉션, 희수의 개발·기술 제작, OpenAI Codex의 AI 구현 보조를 기록한다.
- 공개 승인된 이름 외에 이메일·성·프로필 링크 등 추가 식별 정보는 넣지 않는다.
- 표준 오픈 소스 라이선스를 부여하지 않고 원본 코드와 창작물의 권리를 유보한다. 제3자 자료에는 각 자료의 라이선스를 적용한다.
- 기술 보고서 전체를 검토 진입점으로 쓰지 않고, 플레이 링크와 게임별 확인 질문을 모은 원안 검토 문서를 제공한다.
- `born-from-songs` 저장소의 현재 Git 이력을 공개하고, 게임별 링크는 별도로 안내한다.
- 세 게임을 추가로 공개해 다섯 게임 모두 독립 주소를 제공한다. 통합 허브는 나중에 정한다.

## 현재 구현 사실

- 활성 게임 다섯 개가 각각 독립적인 TypeScript/Vite 웹 앱으로 존재한다.
- 활성 다섯 게임 모두 웹 빌드를 담는 별도 사이트 래퍼가 있다.
- 다섯 사이트 래퍼 모두 공개 배포되었으며 실제 주소는 전달 메시지에서 별도로 공유한다.
- 각 앱은 자체 `package.json`과 진입점을 가지며 다른 게임의 모드나 에피소드로 묶이지 않는다.
- 로컬 전용 원본 영역은 `.gitignore` 경계 안에 있다.
- 예전 경로와 새 경로의 대응은 [저장소 구조와 이전 경로](REPOSITORY_MAP.md)에 기록한다.
- [원안 검토 안내](CREATIVE_REVIEW.md)에 현재 플레이 가능 여부와 다섯 게임의 검토 질문을 모았다. 실제 공개 주소는 전달 메시지에서 별도로 공유한다.

## 제안 — 미채택

- 루트 통합 실행 명령이나 workspace 도구는 반복 작업의 필요가 확인된 뒤 검토한다.
- 여러 게임에 공통 패키지를 도입하는 대신, 먼저 실제 중복과 독립성 저하 여부를 확인한다.
- 원본에서 공개 문서로 내용을 승격할 때에는 공개 가능성 검토와 사용자 확인 절차를 둔다.

위 항목은 현재 구조에 반영된 결정이 아니다.

## 미결정

- 다섯 개별 사이트를 한 주소로 묶는 통합 허브의 필요 여부와 배포 절차
- 게임·기여물별 저작권 귀속
