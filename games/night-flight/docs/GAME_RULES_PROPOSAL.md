# 야간비행 — 게임 규칙 재설계안

상태: **코어 규칙 재설계·90초 웹 프로토타입 구현**

이 문서는 현재의 목적지 클릭·전부 방문·고정 글자 조합 루프를 대체하기 위한
설계안이다. 사용자가 직접 밝힌 방향과 아직 채택되지 않은 세부 규칙을 구분한다.

## 직접 피드백

- 현재 구현은 목적지를 누르고 정해진 글자 순서를 맞추는 데 그쳐 게임으로서의
  선택, 숙련과 결과가 약하다.
- 서로의 궤도를 맞추는 과정에 중력의 상호작용 같은 물리 법칙을 일부 적용해도
  좋다.
- 글자 조합을 필수로 유지하기보다 여러 사람과 만나며 점수나 색을 쌓는 방식도
  가능하다.
- 여행자는 무채색으로 출발해 만남을 거치며 다양한 색을 입은 존재로 변할 수
  있다.
- 생애에는 시간 제한이 있고, 여행자도 나이 들어 별처럼 소멸한다.
- 지나가는 행성은 무한히 생성되지 않고 시간이 갈수록 줄어들어 노화를 느끼게
  해야 한다.
- 웹 구현이 이 규칙을 충분히 표현하기 어렵다면 Unity도 후보로 검토한다.
- 여행자는 원형보다 무채색 우주비행사 형태로 보이고, 만남의 색이 외곽 띠가
  아니라 우주복 내부를 비율대로 채워야 한다.
- 행성에는 색 이름 대신 사람의 흔적 같은 메시지가 남고, 플레이 종료 때 최종
  색과 메시지를 다음 플레이에 이어줄 수 있어야 한다.
- 가까워질수록 커지는 중력은 오라로 보여주되 오라 안쪽에서는 안쪽 접근 속도가
  조금씩 느려져야 한다. 표면 접촉은 충돌이며 색 일부를 잃는다.
- 외로움과 색의 의미를 게임 속 작가 문장으로 직접 설명하지 않고 시각적
  미장센과 규칙으로 보여줘야 한다.

## 사용자 결정

- 분위기 조정보다 게임 규칙을 먼저 다시 설계한다.
- 궤도를 맞추는 이동과 만남을 새 코어 플레이의 중심으로 삼는다.
- 유한한 생애, 노화와 소멸을 플레이 규칙에 포함한다.
- 고정 글자 순서 맞히기를 필수 코어로 유지하지 않는다.
- 무채색 우주비행사 내부의 색 면적, 메시지를 품은 행성, 공명층의 안쪽 방사
  감쇠와 충돌 색 손실을 규칙으로 채택한다.
- 결말의 익명 메시지와 최종 팔레트를 서버에 저장해 다음 회차 행성에 사용하고
  기본 유해 표현 필터를 둔다.
- 인트로와 결말에서 관계 메타포를 설명하는 작가 문장을 사용하지 않는다.

Unity 채택, 숫자 점수 표시, 색 혼합 공식과 정확한 생애 길이는 아직 결정하지
않았다.

## 한 문장 규칙

> 유한한 생애 동안 움직이는 사람들의 중력을 읽고 궤도를 맞춰 함께 가며,
> 서로에게 남긴 색으로 자신의 항로를 완성한다.

## 한 바퀴의 코어 루프

`신호를 발견한다 → 누구를 향할지 고른다 → 추진해 진입 각도를 만든다 →
중력에 휘는 항로를 보정한다 → 상대속도를 맞춰 공명한다 → 더 머물지 떠날지
결정한다 → 달라진 속도와 색으로 다음 신호를 찾는다`

### 1. 이동과 중력

- 여행자와 행성은 위치, 속도, 질량을 가진 2차원 물체로 움직인다.
- 가까운 행성의 중력이 여행자의 속도와 진행 방향을 휘게 한다.
- 여행자는 짧은 추진으로만 속도를 바꾸며, 입력을 놓으면 현재 속도로 유영한다.
- 너무 가까이 직선으로 돌진하는 것보다 접근 각도와 상대속도를 맞추는 것이
  중요하다.
- 완전한 천체 시뮬레이션 대신 가까운 물체끼리만 계산하고 힘의 최댓값을 제한한
  게임용 중력 모델을 사용한다.
- 만남이 성립하면 행성의 경로도 아주 조금 흔들리고 여행자의 색 흔적을 받아,
  서로 영향을 남겼다는 사실을 보이게 한다.

### 2. 궤도 공명

- 단순 충돌이나 방문 버튼으로는 만남이 성립하지 않는다.
- 일정 거리 띠 안에서 상대속도를 낮게 유지하면 `공명`이 시작된다.
- 공명 상태를 유지하는 동안 두 물체는 함께 곡선을 그리고 색이 오간다.
- 거리가 너무 멀어지거나 상대속도가 커지면 공명이 끊긴다.
- 오래 안정적으로 공명할수록 더 진한 색과 높은 공명값을 얻는다.

거리, 상대속도, 유지 시간의 정확한 수치는 조작 프로토타입에서 조정한다.

### 2-1. 공명층과 표면 충돌

- 먼 거리부터 행성의 중력은 계속 여행자를 끌어당긴다.
- 거리와 실제 중력 세기가 커질수록 오라, 휘어진 먼지와 예상 항로가 선명해진다.
- 오라 안에서는 행성 쪽으로 들어가는 상대 방사 속도만 점차 감쇠한다. 접선
  속도를 보존해 궤도를 만들 수 있고, 별도의 강한 척력을 사용하지 않는다.
- 표면에 접근 중 완전히 닿으면 거의 비탄성 충돌이 일어나고, 충격에 따라 현재
  색의 5~12%가 흩어진다. 색 입자와 행성 표면의 얼룩이 손실을 보여준다.
- 이미 행성에서 멀어지는 중에는 겹침만 바로잡고 속도를 다시 행성에 붙잡지
  않는다.

### 3. 머무름과 이탈

- 공명 중에도 플레이어는 계속 작은 보정을 해야 한다.
- 오래 함께하면 색이 깊어지고 공명값이 커지지만, 생애 시간은 흐르고 다른
  행성은 계속 이동한다.
- 일찍 이탈하면 다음 만남을 쫓을 시간이 남지만 현재 색은 옅게 남는다.
- 어떤 행성은 자연스럽게 오래 나란히 가고, 어떤 행성은 궤도 곡률이 달라 큰
  노력을 들여도 결국 멀어진다.

따라서 만남은 보상 카드가 아니라 시간과 항로를 쓰는 선택이 된다.

### 4. 색과 점수

- 여행자는 명도만 있는 무채색으로 시작한다.
- 행성마다 고유한 색 성분이 있고, 공명 시간과 안정도에 따라 여행자에게 색이
  섞인다.
- 여행자가 가진 색도 행성에 일부 남는다.
- 공명값은 판정을 위한 내부 점수로 사용하되, 플레이 중에는 숫자보다 색의
  농도, 입자와 항로 흔적으로 피드백한다.
- 결과 화면에는 만난 수, 가장 오래 함께한 시간, 최종 색과 항로를 보여줄 수
  있다. 이를 삶의 우열을 정하는 총점으로 표현하지 않는다.

현재 구현에서는 행성이 가진 1~4색 팔레트가 우주복 내부를 기여도에 따라
채우며, 여행자의 색은 충돌 때 행성 표면 얼룩으로 남는다. 공명만으로 여행자의
색이 행성에 얼마나 옮겨갈지는 아직 미결정이다.

### 4-1. 남겨진 메시지

- 행성의 오라에 들어오면 익명 메시지 일부가 보이고, 공명하면 전체가 드러난다.
- 생애가 끝난 플레이어는 자신의 최종 팔레트와 최대 60자 메시지를 선택적으로
  남길 수 있다. 이름, 좋아요, 순위와 답글은 표시하지 않는다.
- 서버 데이터가 부족하거나 일시적으로 읽히지 않으면 공개 가능한 seed를
  사용한다.
- 1차 공개 안전장치로 욕설·위협·링크·연락처를 거절하고 저장 횟수를 제한한다.
  신고, 관리자 삭제와 검수 정책은 별도 결정이 필요하다.

### 5. 유한한 생애와 노화

- 완성 회차의 생애 시간은 잠정 5~7분이며, 현재 첫 조작 실험은 90초다.
- 전체 행성은 미리 정한 유한한 수만 한 번씩 지나가며 무한 생성하지 않는다.
- 초반에는 여러 신호가 겹쳐 선택을 요구하고, 후반에는 새 신호가 줄어 빈 공간과
  침묵이 길어진다.
- 나이가 들수록 최대 추진력이 약해지거나 방향 전환에 더 긴 시간이 필요하다.
- 마지막 구간에는 새 행성이 나타나지 않고 기존 행성도 화면 밖으로 멀어진다.
- 생애가 끝나면 여행자는 지금까지 얻은 색의 입자로 흩어지고, 지나온 항로와
  상대에게 남긴 색만 잠시 우주에 남는다.

노화에 따른 조작 저하는 감정 전달보다 불쾌감이 커지지 않는 범위에서만 적용한다.

### 6. 결과와 다시 하기

- 모든 행성을 한 판에 만나는 것은 불가능하게 설계한다.
- 신호를 놓치거나 공명에 실패해도 별도의 게임오버는 없지만, 그 만남은 다시
  돌아오지 않는다.
- 최종 결과는 정답 단어가 아니라 여행자의 색, 항로의 모양, 만남의 길이와
  상대에게 남긴 흔적이다.
- 결과에서는 최종 팔레트와 함께 익명 메시지를 남기거나 말없이 떠날 수 있다.
- 다시 시작하면 행성의 등장 순서나 초기 궤도 위상이 달라져 다른 선택과 색이
  나온다.

## 현재 구현에서 제거할 규칙

- 여섯 목적지를 모두 방문해야 결말로 가는 조건
- 목적지 클릭 자동 항해와 근접 후 방문 버튼
- 방문하면 반드시 같은 기억과 글자 조각을 받는 보상
- 세 개의 고정 정체성과 두 글자 정답 순서 맞히기
- 방문 여부만 남기고 만남의 시간과 방식은 반영하지 않는 상태값

## 첫 구현 절단점 — 구현 사실

인물·사건 콘텐츠를 넣기 전에 추상적인 여행자와 행성만으로 다음을 검증한다.

1. 여행자 한 명, 한 번씩 지나가는 행성 여섯 개, 유한한 90초 생애를 만들었다.
2. 추진, 관성, 제한된 상호 중력과 예상 항로 표시를 구현했다.
3. 거리와 상대속도로 공명 시작·유지·이탈을 판정한다.
4. 공명 안정도에 따라 여행자의 색, 교환 입자와 항로 흔적이 변한다.
5. 65초 이후 새 행성이 끊기고 90초에 여행자가 색 입자로 소멸한다.
6. 무채색 우주비행사 내부의 다색 채움, 공명층의 안쪽 방사 감쇠와 충돌 색
   손실을 구현했다.
7. D1 기반 익명 메시지 저장·재등장과 1차 유해 표현·연락처 필터를 구현했다.

이 조작 실험이 재미와 감정을 만들지 못하면 기억 콘텐츠나 시각 자산을 추가하지
않는다.

## 웹과 Unity 경계

### 우선안: 현재 웹 앱 안의 2D Canvas

- 한 화면에서 열 개 미만 물체의 중력, 관성, 궤도 예측과 입자를 계산하는 것은
  현재 TypeScript 웹 앱에서도 충분히 시험할 수 있다.
- 기존 배포 경계를 유지하고 링크로 바로 플레이할 수 있어 해커톤 검증이 빠르다.
- 90초 2D Canvas 프로토타입을 구현하고 데스크톱·모바일 브라우저에서 확인했다.

### Unity 전환을 검토할 조건

- 3D 공간과 카메라 회전이 코어 플레이에 반드시 필요하다.
- 다수 입자와 조명, 후처리를 브라우저 구현으로 목표 프레임에 유지하지 못한다.
- 단순화한 2D 중력으로는 원하는 조작 감각을 만들 수 없다는 플레이 테스트 결과가
  나온다.

현재 규칙만으로는 Unity가 필수라는 근거가 없으므로 웹을 우선한다. Unity 전환은
웹 프로토타입 실패가 확인된 뒤의 별도 사용자 결정으로 남긴다.

## 미결정

- 숫자 점수를 결과 화면에 표시할지, 색과 기록만 보여줄지
- 행성이 모두 사람을 나타낼지, 경험을 나타내는 다른 천체도 둘지
- 색을 단순 혼합할지, 만남마다 무늬·질감까지 남길지
- 메시지의 최종 문체·감정 범위와 신고·관리자 검수·삭제 정책
- 노화가 추진력, 회전성, 신호 감지 중 무엇을 변화시킬지
- 한 판의 최종 시간과 전체 행성 수
- 궤도 예측선을 항상 보여줄지 보조 모드로만 제공할지
- 기존의 처음 질문을 삭제할지, 목표가 아닌 출발 기록으로만 남길지
